最终配置的 32K/96K 冷输入均找到 3/3 条目，缓存扩展也均 3/3。96K 缓存扩展首字 0.438 秒、请求 2.360 秒，实际复用 98,300 tokens、新处理 19 tokens。这是历史原生 prefix-extension 工作负载，不等同于下面的标准聊天模板对照。

## 公平 96K 长对话 MTP 对照

同一优化 DLL、相同主模型、Q8_0 KV、batch/ubatch 2048、上下文 114,688、单槽、温度 0.2、seed 20261026。两组使用相同 token 数组；[输入指纹](../results/2026-10-24-nemotron/long-chat-input-hashes.json)。MTP 为 Q8 drafter、n-max 7、p-min 0.6。

冷检索预填充：关 1055.91 tok/s，开 940.62 tok/s；两组都 3/3 正确，缓存检索也都 3/3。后续三项两组都复用 98,374 tokens。

开启 MTP 后，缓存检索生成约快 45%，代码约快 3%，英文说明约慢 20%。英文输出为 712 vs 549 tokens，总耗时不能作为固定输出长度对照；代码两组均达到 768 token 上限，不应当作完整代码质量得分。接受率较高也不保证总时间更短，draft 计算与调度同样有成本。

因此保留默认 MTP 的长对话 preset，同时提供冷输入优先 preset；这里的“默认”只指项目启动配置，不代表本机当前服务已被改动，也不是所有长文本都会更快。
